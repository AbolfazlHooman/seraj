# سراج | SERAJ

اپ وب (فایل `www/index.html`) که با Capacitor به APK اندروید تبدیل می‌شود.

## گرفتن APK
0. **یک‌بار** کلید امضا را تنظیم کنید (بخش «کلید امضا» پایین‌تر).
1. پروژه را در یک مخزن GitHub بگذارید (شاخهٔ `main`).
2. به تب **Actions** بروید؛ workflow با نام **Build APK** خودکار اجرا می‌شود
   (یا از **Run workflow** دستی اجرایش کنید).
3. بعد از پایان (حدود ۴ تا ۷ دقیقه) در پایین صفحهٔ اجرا، بخش **Artifacts** فایل `seraj-apk` را دانلود کنید.
4. فایل zip را باز کنید و `app-debug.apk` را روی گوشی نصب کنید.

## به‌روزرسانی اپ
فایل `www/index.html` را عوض و commit کنید؛ APK جدید خودکار ساخته می‌شود.

## مجوز
کد این پروژه تحت مجوز MIT منتشر شده است (فایل `LICENSE`).

این مجوز فقط شامل کد برنامه است و محتوای شخص ثالث را پوشش نمی‌دهد:
- متن قرآن (در صورت وارد کردن دادهٔ Tanzil) تابع شرایط خود Tanzil است.
- صوت تلاوت از سرویس‌های mp3quran و everyayah پخش می‌شود و متعلق به صاحبان آن‌هاست.

## انتشار وب (GitHub Pages)
در **Settings ← Pages** گزینهٔ Source را روی **GitHub Actions** بگذارید.
از آن به بعد با هر commit، پوشهٔ `www` خودکار منتشر می‌شود و لینک در تب Actions نمایش داده می‌شود.

## نصب روی دسکتاپ (PWA)
بعد از انتشار روی GitHub Pages، سایت را در Chrome یا Edge باز کنید و از نوار آدرس (یا منوی مرورگر) گزینهٔ **Install** را بزنید.
اپ با آیکن خودش در پنجرهٔ جدا باز می‌شود و صفحه‌های برنامه بدون اینترنت هم کار می‌کنند.
صوت تلاوت و فونت‌های اولیه برای بار اول به اینترنت نیاز دارند.

اگر بعد از تغییر `index.html` نسخهٔ قدیمی دیده شد، در `www/sw.js` مقدار `V` را عوض کنید (مثلاً `seraj-v2`).

## پخش آفلاین صوت (فقط اپ اندروید)
در صفحهٔ هر سوره دکمهٔ «دانلود برای پخش آفلاین» هست. فایل در حافظهٔ داخلی اپ ذخیره می‌شود و با دکمهٔ «حذف از دستگاه» پاک می‌شود.
اگر فایل کامل سوره دانلود نشود، دانلود به‌صورت آیه‌به‌آیه ادامه پیدا می‌کند.
در نسخهٔ وب و دسکتاپ این دکمه نمایش داده نمی‌شود.

## کلید امضا و به‌روزرسانی APK
اندروید فقط وقتی نسخهٔ جدید را روی نسخهٔ قبلی نصب می‌کند که با **همان کلید** امضا شده باشد.
1. در مخزن: **Settings ← Secrets and variables ← Actions ← New repository secret**
2. نام: `DEBUG_KEYSTORE_B64`
3. مقدار: کل متن فایل `DEBUG_KEYSTORE_B64.txt` (یک خط طولانی، بدون فاصله و خط اضافه)
4. این فایل را **داخل مخزن نگذارید** و پیش از انتشار در فروشگاه، کلید اختصاصی خودتان را بسازید.

## اعلان نسخهٔ جدید
با هر تغییر در `www/`، workflow یک Release با نام `build-N` می‌سازد و APK را به آن پیوست می‌کند.
اپ هنگام باز شدن (حداکثر هر ۳ ساعت) آخرین Release را بررسی می‌کند و اگر نسخه‌ای جدیدتر بود، نوار «نسخهٔ جدید آماده است» نشان می‌دهد.
مخزن باید **عمومی (Public)** باشد تا اپ بتواند Release را بخواند و فایل را دانلود کند.
